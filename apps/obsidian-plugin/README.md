# Research-based Learning Community · Obsidian 插件

> 仓库内名称：`Research-based Learning Community`（manifest `name`）；作者：`denghao`；插件 id：`research-learning-community`。

信息架构：**领域 → 文献 → 精读卡片**。先建领域，再往里添文献，精读卡片挂在具体文献下面。

## 安装（手动）

1. 在你的 Vault 里建目录：`.obsidian/plugins/research-learning-community/`
2. 放入 `main.js`、`manifest.json`、`styles.css`
3. Obsidian → 设置 → 第三方插件 → 关闭安全模式 → 启用「研究性学习社区」

也可以直接用 `research-learning-community-0.2.0.zip` 解压到上述目录。

## 首次配置

设置 → 研究性学习社区：

| 项 | 说明 |
|---|---|
| 展示名 / 公开 handle | handle 是对外路由用的英文 id，真名只在班内可见 |
| AI 接口地址 | 任何 OpenAI 兼容端点，如 `https://api.deepseek.com/v1` |
| API Key | 自带 Key，只存本机 `data.json` |
| 模型 | 如 `deepseek-chat` |
| 测试连接 | 先点这个，确认端点/Key/模型三者都通 |
| 服务端地址 / 设备令牌 | 可留空；留空时发布只进本地队列，不上传任何内容 |

## 信息架构

```
领域/
├─ 文献综述.md
└─ 文献/<citekey>/
     ├─ <citekey>.md              ← 文献信息（与文件夹同名）
     ├─ <citekey>-略读.md         ← 略读报告
     ├─ <citekey>-dr-xxxxxxx.md   ← 精读卡片（直接放在文献文件夹）
     ├─ <citekey>-pc-xxxxxxx.md   ← 实践卡片
     └─ assets/                   ← Mermaid 视觉图
```

**命名规则：文件夹名 = 里面所有文件的前缀。** 这样在文件树里一眼能看出某个文件属于哪篇文献；卡片不再埋在 `精读卡片/` 子目录里，少一层折叠。

**为什么文献要单独一层**：精读卡片天然属于某篇文献，挂在「主题」下就回答不了「这篇文献产出了几张卡片」；文献有自己的阅读状态，总览才能显示进度。

## 用法

| 操作 | 入口 |
|---|---|
| 打开总览（右侧栏） | **左侧笔记本图标**，或命令面板「打开研究性学习总览」 |
| 新建领域 | 总览右上角「＋ 领域」——**创建后立即调用 AI 生成综述** |
| **生成领域文献综述** | **点领域名**（首次点击即生成；已有综述则打开它），或领域行「生成综述」/「重生成」 |
| **选择候选文献** | 综述生成后，领域行出现「选文献」——勾选、核验 DOI、加入领域 |
| 手动添加文献 | 总览右上角「＋ 文献」，或领域行里的「＋ 文献」 |
| **生成略读报告** | 文献行里的「略读」——自动带出文献笔记的「## 摘要」 |
| **下载原文 PDF** | 文献行里的「下载原文」——只下开放获取，落到 `文献/<citekey>/原文.pdf` |
| 新建精读卡片 | 文献行里的「＋ 精读」，或命令面板「新建精读卡片」后选文献 |
| AI 起草思考部分 | 卡片弹窗里，**必须先粘贴原文摘录**——AI 不会替你编原文 |
| 生成 Mermaid 视觉图 | 卡片弹窗里，需要先写出 Aha |
| 校验当前卡片 | 命令面板「校验当前卡片」 |
| **发布当前卡片** | 三个入口：① 总览里卡片行右侧「发布」按钮 ② 文件列表右键 →「发布到研究性学习社区」 ③ 命令面板「发布当前卡片」 |
| 查看已发布 | 卡片行上显示「已发布」，点击打开门户链接 |
| 重试待发布队列 | 点右下角状态栏，或总览里的「重试」 |

## 领域 → 综述 → 选文献 的完整流程

1. 点「＋ 领域」→ 创建目录后**立即调用 AI 生成综述**，写到 `领域/<名>/文献综述.md`
2. 综述末尾带一段**机器可读的候选文献清单**（HTML 注释，正文里看不见）
3. 点「选文献」→ 勾选想要的 → 点「核验全部 DOI」→ Crossref 逐条验证
4. 只有核验通过的才默认允许入库；未核验的要手动打开开关
5. 入库后每篇文献建 `文献/<citekey>/<citekey>.md`，`＋ 卡片` 就能写卡片

**为什么要有核验这一步**：模型可以编标题、编作者、编 DOI，但编不出 Crossref 里真实存在的记录。核验是这条链路上唯一能证伪 AI 的环节，所以它不能被跳过。

## 略读报告

点文献行的「略读」：

1. 输入框自动带出文献笔记里「## 摘要」的内容；没有就手动贴一段摘要或正文片段
2. AI 产出四节：研究问题 / 方法 / 结论 / 是否值得精读（3 条理由）
3. 报告存到 `文献/<citekey>/<citekey>-略读.md`，frontmatter 带 `decision`
4. **结论驱动文献状态**：
   - `deep_read` → 文献状态变成「精读中」
   - `skip` → 变成「已跳过」
   - 解析不到结论 → 状态不变（不会因为模型少写个引号就误标）

材料不足时，AI 被要求写「摘要未提供，需要看原文」，而不是猜。

## 下载原文（仅开放获取）

点文献行的「下载原文」：

1. 用 DOI 查 OpenAlex：`api.openalex.org/works/doi:<DOI>`
2. 取 `best_oa_location.pdf_url`，退化到 `primary_location.pdf_url`
3. 校验返回的 `content-type` 必须含 `pdf`（很多 OA 链接会重定向到登录页）
4. 保存到 `文献/<citekey>/原文.pdf`，并在文献笔记 frontmatter 写 `pdfPath`

**三条硬边界**：

- 只下开放获取。非 OA 的直接提示「这篇不是开放获取」，不绕付费墙。
- 不是 PDF 就不存。宁可失败，也不要在 Vault 里塞一个登录页 HTML。
- PDF 只落本地，**永不上传**。发布链路（`assets` 白名单）继续只接受 png/jpeg/webp。

## 总览视图

- 四个数字：领域 / 文献 / 卡片 / 精读
- 待发布提醒（有 outbox 条目时才出现）
- 每个领域：文献数、卡片数、每篇文献的状态标签与卡片数
- 点文献标题打开文献笔记，点卡片标题打开卡片
- 挂不到文献的卡片会进「未挂到文献的卡片」，不会被静默丢掉
- 监听 Vault 变更自动刷新（350ms 防抖）

## 示例：从零到第一张卡片

1. 点左栏笔记本图标 → 「＋ 领域」→ 输入「课程与教学论」
2. 「＋ 文献」→ 填标题、作者、年份、DOI
3. 文献行点「＋ 精读」→ 粘一段原文摘录 → 「AI 起草思考部分」→ 逐条改成自己的话 → 保存
4. 回到总览，文献状态变成「已出卡片」，卡片数 +1

## 已知限制

- 发布链路尚未与真实服务端联调；multipart 上传只在单测里验证过 body 结构。
- Mermaid 视觉图只落盘 `.mmd`，插件内不渲染预览（Obsidian 原生可看）。
- 图片资产仅支持 png/jpeg/webp；PDF 与 SVG 被白名单挡住。
- 中文作者没有拼音转换，citekey 会回落到标题前三词或 `lit-nd-xxxx`。
