# ADR-004：发布即不可变快照 + 修订链

## Status
Accepted（2026-11-13）

## Context
学生会在发布后继续打磨卡片（补 Aha、换图、改错别字），而其他同学已经在评论区讨论。如果把"发布"实现成"服务器持有本地文件的副本并原地覆盖"，会带来：
- 讨论上下文丢失（评论引用的段落被改没了）；
- 无法回答"这条评论当时针对的是哪个版本"；
- 撤回/申诉时没有证据。

## Decision
一次发布产生一条**不可变**的 `publication_revision` 记录：

- `publication` 是"话题/卡片身份"，持有 `current_revision` 指针与去规范化的互动计数；
- `publication_revision` 逐字保存 `body_md`、渲染后的 `body_html`、`frontmatter`、`content_hash`；
- 学生再次发布同一 `clientCardId` 且内容不同 → 追加 `revision+1`，指针前移；
- **评论挂在 `publication.id` 上**，不挂在 revision 上；门户默认显示最新修订，历史修订可通过 `/publications/{id}?revision=n` 查看（仅作者与管理员）；
- 撤回只是 `status=withdrawn`，数据保留。

## Consequences
**变容易**
- 讨论永远不失效；
- 审核有完整证据链；
- 客户端幂等实现简单（同 hash 直接返回已有记录）。

**变难**
- 存储冗余（每版都存全文；单卡 10KB 级别，可忽略）；
- 阅读页需要处理"评论早于当前修订"的语义提示（可选 UI：在修订变更时给旧评论加"针对 v2"标记）。

## Alternatives considered
| 方案 | 否决理由 |
|---|---|
| 原地覆盖（只存最新版） | 讨论上下文丢失，无法审计 |
| 每次修订新建 publication | 评论与链接会被打散，URL 不稳定 |
| 存 diff/patch 链 | 读取需重放，且 md diff 容易冲突，收益不足 |
