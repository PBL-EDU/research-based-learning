# ADR-001：本地优先，Vault 是私域唯一真相

## Status
Accepted（2026-11-13）

## Context
学生使用 Obsidian 完成"文献综述 → 略读 → 精读卡片 → 实践卡片 → 总结"的长流程，单次研究可能持续数周。过程中存在大量半成品、失败稿、AI 重试记录、私人生活体验描述。同时服务器还要承载公众浏览与讨论。

若把服务器当真相源，会带来三个立刻出现的问题：
1. 没网、没账号、AI 没配额时，研究流程直接卡死；
2. 所有私密草稿必须上传，与"仅学生选择才上传"的产品红线冲突；
3. 三端同时写同一份长文，需要合并策略（CRDT/OT），复杂度远超收益。

## Decision
本地 Vault（Markdown）是**私域数据的唯一真相**。服务器只持有"学生显式发布时的不可变快照"，并且：
- 跨端写方向只有一条：本地 → 服务器（且必须由可见的用户动作触发）；
- 服务器永不回写 Vault 的业务内容，只回写发布回执（`id/url/revision/hash`）；
- 服务器 → 本地的一切其他数据（讨论树、他人卡片、模板）都是只读复制，复制后与来源解耦。

## Consequences
**变容易**
- 断网可完成全部研究流程；
- 无同步冲突，不需要 CRDT；
- 学生退课/换设备，数据仍在本地，可随时脱离系统。

**变难**
- 多设备之间不自动同步（接受：用 Git/Syncthing 自行解决，不在产品范围内）；
- 服务器无法做全校级的"覆盖率统计"（只统计已发布部分，接受）；
- 需要 outbox、幂等、回写等工程细节来补足"发布不可靠"的风险。

## Alternatives considered
| 方案 | 否决理由 |
|---|---|
| 服务器为中心 + 插件仅做客户端 | 违反产品红线；离线不可用；私密草稿必须上传 |
| 双向同步（类 Obsidian Sync） | 需要冲突合并，长文合并质量不可控，且把服务器变成笔记盘 |
| 本地为主 + 定期自动全量上传 | 学生失去对"哪些被上传"的控制权，合规风险 |
