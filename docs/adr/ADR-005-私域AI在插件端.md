# ADR-005：私域内容生成 AI 在插件端

## Status
Accepted（2026-11-13）

## Context
系统的 AI 能力横跨两端：文献综述、略读报告、Aha 五点、实践复盘、视觉图（私域）；OG 分享图、内容审核、语义检索（公域）。

若把 AI 全部放在服务器：
- 学生的选题犹豫、失败稿、生活体验描述都要上传（触碰产品红线）；
- 平台承担全部 token 成本，且额度滥用难以约束；
- 服务器成为单点，AI 供应商一抖动，所有人的研究流程中断。

若全部放在插件端：
- 公域需要的 OG 图/审核仍必须服务端做（涉及公开内容安全）；
- 学生没配 Key 时功能完全不可用。

## Decision
**按数据私密性分界**：

| 数据性质 | 落点 | 谁付费 |
|---|---|---|
| 私域内容（草稿、生活体验、失败尝试） | 插件端直连 LLM | 学生自带 Key（可选平台代付，Phase 3 再议） |
| 公域呈现加工（OG 图、mermaid 渲染、审核） | 服务端 worker | 平台 |
| 契约（模板、JSON Schema、提示词） | 服务端注册表下发，插件缓存 | 平台维护 |

服务端**不代理**学生的大模型调用，因此不存储学生的 prompt 与生成结果。

## Consequences
**变容易**
- 隐私边界清晰，学生可自查"什么离开了我的电脑"；
- 平台成本可预测（只有 OG 与审核）；
- 换模型/换供应商不需要动服务端。

**变难**
- 学生上手成本提高（要自备 Key）→ 用"降级模式"缓解：无 Key 时模板照样可用，只是不自动生成；
- 无法统一做内容质量兜底（只能在发布时做结构与红线校验）；
- 若将来改为平台代付，需要新增 `ai-gateway` 模块（配额、审计、密钥托管），属于可增量演进的方向，不影响当前边界。

## Alternatives considered
| 方案 | 否决理由 |
|---|---|
| 全服务端 AI + 代理 | 私密数据过服务器；成本不可控；单点故障 |
| 全插件端 AI | 公域 OG/审核无法在插件完成 |
| 服务端做"提示词即服务"并代理调用 | 等于把密钥交给服务器，仍需审计，收益低于成本 |
