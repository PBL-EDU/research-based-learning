## 1. 四条已定

| # | 问题 | 决定 | 对架构的影响 |
|---|---|---|---|
| **D-01** | 公众号主体 | **个人主体** | 发布接口不可用 → 发布链路降级为「可移植发布包 + 人工发布」，见第 2 章 |
| **D-02** | AI 谁付费 | **学生自带 API Key（BYO Key）** | ADR-005 成立；**不建** AI 网关、配额、代付、审计 |

| **D-04** | 首期规模 | **单班 ≤30 人** | 不引入多租户；一个 cohort 即全部；权限模型最简 |

**D-02 的一处连带风险**（提前说清）：BYO Key 把配置成本转给了每个学生。30 人班里只要有一半配不通，P1 的研究流水线就跑不起来。缓解方案写进 P1：提供"一键填入 OpenAI 兼容端点"的设置向导 + 连通性自检按钮 + 一份图文配置指引，**不要指望学生自己看文档**。

## 2. 个人主体：五个连带影响

### 2.1 发布能力从「接口」降级为「发布包」——这是本次最重要的一条

官方文档写明（引自 [公众号与小红书方案](./研究性学习社区-公众号与小红书发布运营方案.md) §1.3）：

> 2025 年 7 月起，个人主体账号、企业主体未认证账号及不支持认证的账号将被回收**发布能力**接口的调用权限。

而**草稿接口对个人主体是否开放，官方文档没有明确标注**。所以不能把产品建立在「草稿接口一定可用」之上。

**架构结论：把「发布物」定义成可移植的发布包，微信 API 只是可选加速器。**

```
发布物 PublishBundle（P0 第一等公民，不依赖任何平台 API）
├─ article.html      公众号可粘贴的富文本（内联样式、图片走本地引用）
├─ article.md        同一内容的 Markdown（门户/备份/其他平台）
├─ assets/           图片（已转 WebP，含 1200/480 两档）
├─ meta.json         标题、摘要、作者、封面、话题标签、AI 声明
└─ manifest.json     校验和与生成版本

可选通道（实测通过才启用）
├─ CH-1 draft/add      → 自动建草稿，学生后台点发布
├─ CH-2 uploadimg      → 正文图换微信 URL（不换则粘贴后图裂）
└─ CH-3 freepublish    → 个人主体不可用，仅为未来认证后预留
```

**为什么必须在 P0 就做发布包**：如果先做草稿接口、等发现不可用再回头，渲染器、图片处理、排版模板全部要重写一遍。反之，发布包先成立，草稿接口只是"把 html 推过去"的 20 行适配器。

### 2.2 微信登录不可用

微信登录需要认证服务号。个人主体下门户鉴权**只保留邮箱验证码**（架构文档 §2.3 已列为"后期"），P0 直接按邮箱验证码实现，不留微信登录的抽象层。

### 2.3 ICP 备案可以用部署位置绕开

备案是**国内服务器**的要求，周期 2–4 周，比写代码长。30 人规模有两条路：

| 方案 | 周期 | 代价 | 建议 |
|---|---|---|---|
| 国内 VPS + ICP 备案 | 2–4 周（须先有主体） | 需备案主体资质，个人备案不能做经营性内容 | **推荐**，见下方修正 |
| 香港/新加坡 VPS | 当天 | 大陆访问延迟 ~50–150ms，无备案 | 暂缓（原推荐，已被下方修正推翻） |

> **2026-11-14 修正（D-05，待你确认）**：重新评估后改为**推荐境内轻量服务器 + ICP 备案**，撤回「香港内测期」的原建议。核心理由是**用户含未成年人**——未满 14 岁的个人信息属《个保法》第 28 条敏感个人信息，出境需单独同意 + 影响评估 + 标准合同备案，行政成本远高于一台服务器一年。完整论证、成本与部署清单见 [deploy/README.md](../deploy/README.md)。
>
> 这条不阻塞 P0：P0 在本地 docker-compose 跑，不依赖公网域名。

### 2.4 原创声明、群发、接口权限全部是人工

- 原创声明**没有接口**，只能在公众号后台勾选。
- 群发 1 次/天且**不可撤回**，MVP 不做群发，只用「发布」（freepublish）或纯人工。
- 接口权限以目标账号后台「设置与开发 → 接口权限」实测为准。

### 2.5 合规责任前移到「发布包生成」环节

发布包一旦导出，内容就脱离了系统管控。所以**校验必须发生在导出之前**，且要有阻断式规则：

| 规则 | 实现位置 | 失败表现 |
|---|---|---|
| AI 生成内容必须标注 | 发布包 `meta.json` 强制字段 `aiAssisted: true`，HTML 末尾插固定声明 | 缺字段 → 拒绝导出 |
| 引用不超过 300 字 | `dr-card@1` 的 `aha.quote` `.max(300)` | 超长 → 拒绝保存 |
| 不得上传 PDF | 资产 MIME 白名单（仅图片） | 非图片 → 拒绝上传 |
| 文献必须可核验 | `source` 需 DOI 或 URL | 缺失 → 拒绝保存 |

## 3. 相对 v1 架构的范围收缩

| 项 | v1 架构 | 锁定后 | 省下的工作量 |
|---|---|---|---|
| 多租户 / 班级体系 | 预留 | **不做**，单 cohort | ~1 周 |
| 学校 SSO | 预留接口 | **不做** | ~0.5 周 |
| AI 网关 / 配额 / 代付 | Phase 3 可选 | **不做**（BYO Key） | ~2–3 周 |
| 微信登录 | Phase 3 | **不做** | ~1 周 |
| 自动发第三方平台 | 明确不建议 | **明确不做** | — |
| 公众号 API 对接 | P3 | **降级为可选通道**，P0 只做发布包 | 不变，但风险解除 |
| 发布包渲染器 | 隐含在门户渲染 | **提到 P0**，成为独立产物 | +3 人日 |

净效果：**总工期缩短约 3–4 周，且把最大的外部依赖（微信接口权限）变成了可选项。**

## 4. 一小时可完成的验证（在你自己的个人号上做，别等）

这是唯一无法在代码里解决的未知数。建议今天就做，因为它决定 CH-1/CH-2 通道是否存在：

| 步骤 | 调用 | 期望 | 失败含义 |
|---|---|---|---|
| 1 | `GET /cgi-bin/token` | 拿到 access_token | 密钥/IP 白名单问题 |
| 2 | `POST /cgi-bin/media/uploadimg` 传一张 png | 返回微信 URL | `48001` = 无权限，CH-2 关闭 |
| 3 | `POST /cgi-bin/draft/add` 建一条草稿 | 返回 media_id | `48001` = 仅剩纯人工粘贴；`40164` = 只是 IP 没加白名单 |
| 4 | 后台看草稿箱 | 能看到草稿 | 能 → CH-1 成立 |
| 5 | `POST /cgi-bin/freepublish/submit` | 预期失败 | 个人主体失败是**预期结果**，记录返回码即可 |

**把 2/3/5 的实际返回码贴给我，我据此决定 CH-1 是否在 P0 实现。**
