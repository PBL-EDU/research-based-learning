# 多应用共用一台服务器（dreamook.com）

> 场景：研究性学习社区已上线，后续还要放「素养教师工作台」等应用。
> 同一台 2C4G 轻量服务器、同一个域名，怎么共存而不互相拖累。

---

## 1. 结论

| 方案 | 做法 | 适用 |
|---|---|---|
| **子域名（推荐）** | `rlc.dreamook.com`、`teacher.dreamook.com` | 每个应用独立技术栈、独立登录、互不干扰 |
| 路径前缀 | `dreamook.com/rlc`、`dreamook.com/teacher` | 只有一个应用时简单，多应用会撞 Cookie/鉴权/静态资源 |
| 独立域名 | `dreamook.com` + `teacherdream.com` | 品牌独立，但**每个主域名都要单独备案** |

**推荐子域名。** 原因：

- 子域名**不需要单独备案**（备案针对主域名 `dreamook.com`，子域名自动覆盖）；
- 每个应用可以用不同的后端端口、不同的登录体系，Cookie 默认不共享（`Domain` 不显式设置时按 host 隔离）；
- Caddy 按 Host 分流，证书自动签发，互不影响。

## 2. 目标架构

```
                         ┌──────────────────────────────┐
   dreamook.com  ───────▶│  Caddy :80/:443              │
   www.dreamook.com      │  按 Host 分流 + 自动 HTTPS    │
   rlc.dreamook.com      │                              │
   teacher.dreamook.com  └──────┬───────────────┬───────┘
                                │               │
                     ┌──────────▼───┐   ┌───────▼────────┐
                     │ rlc-api      │   │ teacher-api    │
                     │ 127.0.0.1:4000│  │ 127.0.0.1:4100 │
                     └──────┬───────┘   └───────┬────────┘
                            │                   │
                     ┌──────▼───────────────────▼───────┐
                     │ PostgreSQL（同一实例，不同库）     │
                     │  rlc  /  teacher_workbench        │
                     │ Redis（不同 DB index + 前缀）      │
                     │ MinIO（不同 bucket）              │
                     └──────────────────────────────────┘
```

**关键纪律**：所有应用只监听 `127.0.0.1`，公网只开 80/443 给 Caddy。谁的端口都不直接对外。

## 3. 备案怎么算

| 情况 | 是否需要新增备案 |
|---|---|
| `rlc.dreamook.com` | 否，子域名 |
| `teacher.dreamook.com` | 否，子域名 |
| `dreamook.com` 本身 | 已备案（本次） |
| 换成 `teacherdream.com` 这类**新主域名** | **是**，需在腾讯云「新增网站」 |

> 注意：备案填写「网站」时，域名填主域名 `dreamook.com`。管局审核看的是主域名与主体，子域名不单独列。

## 4. 资源怎么分

### 4.1 端口

| 应用 | 端口 | 绑定 |
|---|---|---|
| rlc-api | 4000 | `127.0.0.1` |
| teacher-api | 4100 | `127.0.0.1` |
| 后续应用 | 4200 起 | `127.0.0.1` |

### 4.2 PostgreSQL

同一实例，一应用一库一账号：

```sql
CREATE DATABASE teacher_workbench;
CREATE USER teacher_app WITH PASSWORD '...';
GRANT ALL PRIVILEGES ON DATABASE teacher_workbench TO teacher_app;
\c teacher_workbench
GRANT ALL ON SCHEMA public TO teacher_app;
```

不动 `rlc` 库和 `rlc` 账号，避免互相看到数据。

### 4.3 Redis

同一实例，用不同 DB index + key 前缀：

- rlc：`redis://:密码@127.0.0.1:6379/0`，key 前缀 `rlc:`
- teacher：`.../1`，前缀 `teacher:`

> 更严格的做法是 Redis ACL 建两个用户各自限 DB，但单机场景 DB index + 前缀足够。

### 4.4 MinIO

一应用一 bucket：`rlc-assets`、`teacher-assets`，各自独立 Access Key（或先用同一 root，P1 再拆子账号）。

### 4.5 内存

3.6 GB 是硬约束。两个 Node 应用 + PG + Redis 的实际占用：

| 组件 | 常驻 |
|---|---|
| PostgreSQL | ~500 MB |
| Redis | ~300 MB |
| rlc-api | ~150 MB |
| teacher-api | ~150 MB |
| Caddy | ~30 MB |
| 系统 + Docker | ~400 MB |
| **合计** | **~1.5 GB** |

还有 2 GB 余量，够放第三个轻应用。**判断是否该扩容的信号**：持续 swap 使用 > 30%，或 Node 进程 RSS 持续 > 500 MB。

## 5. Caddy 配置

```caddyfile
{
    email admin@dreamook.com
}

# 研究性学习社区
rlc.dreamook.com {
    encode gzip zstd
    header {
        Strict-Transport-Security "max-age=31536000; includeSubDomains"
        X-Content-Type-Options nosniff
        Referrer-Policy strict-origin-when-cross-origin
    }
    reverse_proxy 127.0.0.1:4000
}

# 素养教师工作台
teacher.dreamook.com {
    encode gzip zstd
    reverse_proxy 127.0.0.1:4100
}

# 主站（可选：聚合页 / 跳转）
dreamook.com, www.dreamook.com {
    root * /var/www/dreamook
    file_server
}
```

**DNS**：阿里云解析里加一条通配：

| 记录 | 主机记录 | 值 |
|---|---|---|
| A | `@` | 139.155.99.183 |
| A | `www` | 139.155.99.183 |
| A | `rlc` | 139.155.99.183 |
| A | `teacher` | 139.155.99.183 |
| A | `*` | 139.155.99.183（可选，省得每加一个应用就改解析） |

Caddy 对每个 host 单独申请证书（HTTP-01），通配解析不影响。若要用一张通配证书，需 DNS-01 插件 + 阿里云 DNS API 密钥，复杂度高一档，暂不需要。

## 6. 每个应用的部署模板

以 teacher 为例，复制 rlc 的模式：

```
/opt/teacher/                 应用目录（代码 + 运行时）
/opt/teacher/app/             构建产物
/opt/teacher/.env             该应用的密钥（600）
/opt/data/teacher/            该应用的数据（上传文件）
/etc/systemd/system/teacher-api.service
```

systemd 单元同 rlc-api，只改：

- `WorkingDirectory=/opt/teacher/app`
- `EnvironmentFile=/opt/teacher/.env`
- `ExecStart=/usr/bin/node dist/index.js`
- `ReadWritePaths=/opt/data/teacher /var/log/rlc`（建议日志分目录）

## 7. 上线顺序建议

1. **现在**：`rlc` 先跑通（已完成），域名备案中
2. **备案通过后**：加 `rlc.dreamook.com` 解析 → Caddy 起 → 关闭 SSH 隧道
3. **教师工作台上线时**：
   - 建库、建 Redis DB、建 bucket
   - 部署 teacher-api 到 4100
   - Caddyfile 加 `teacher.dreamook.com` 段，`systemctl reload caddy`
   - DNS 加 `teacher` 记录（或已配通配则跳过）
4. **每加一个应用**只需：新端口 + 新 Caddy 段 + 新 DNS 记录 + 新 systemd 单元

**不需要**重新备案、不需要换服务器、不需要停机（Caddy reload 是热加载）。

---

## 8. 三个坑

| 坑 | 后果 | 规避 |
|---|---|---|
| 应用监听 `0.0.0.0` 且 ufw 放行端口 | 绕过 Caddy 直接暴露，无 HTTPS、无限流 | 应用一律 `127.0.0.1`；ufw 只开 22/80/443 |
| 两个应用共用同一个 PG 账号 | 一个应用的 bug 能读另一个应用的数据 | 一应用一库一账号 |
| Cookie 不设 `Domain` 却共享子域 | 登录态串味 | 保持默认（host-only），不要手写 `Domain=.dreamook.com` |

---

## 9. 和备案的关系（一句话）

> 备案是「主体 + 主域名」的事，子域名和应用数量都不影响备案；新增**主域名**才需要新增网站备案。
